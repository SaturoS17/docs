---
title: "Payins"
description: "Collect in local currency and get credited in USDT"
---

A payin is a fiat collection: your customer pays in local currency and your
account gets credited in USDT automatically (converted at the current rate,
minus the payin fee).

There are four ways to collect, depending on the country:

| Mode | How it works | Endpoint |
|---|---|---|
| **QR** | You generate a collection QR and your customer scans it | `POST /v1/payins` with `method: "qr"` |
| **Bank transfer** | You announce an incoming deposit with a reference | `POST /v1/payins` with `method: "bank_transfer"` |
| **Active collection (pull)** | You charge the payer directly (with their authorization/OTP) | `POST /v1/payins/collect` |
| **Dedicated deposit account** | You create a fixed destination account (e.g. CLABE) | `POST /v1/payins/deposit-accounts` |

<Note>
Check the available collection corridors with `GET /v1/payins/methods`.
Each country exposes its modes; for example QR in Bolivia and Brazil (PIX),
active collection in Venezuela, and dedicated deposit accounts in Mexico.
</Note>

## QR collection

<CodeGroup>

```bash Bolivia (interoperable QR)
curl -X POST https://exchange.qbank.cl/platform/v1/payins \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "country": "BO",
    "currency": "BOB",
    "method": "qr",
    "amount": "700.00",
    "description": "App top-up",
    "expires_in": 3600
  }'
```

```bash Brazil (dynamic PIX QR)
curl -X POST https://exchange.qbank.cl/platform/v1/payins \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "country": "BR",
    "currency": "BRL",
    "method": "qr",
    "amount": "120.00",
    "description": "Order 7719",
    "expires_in": 1800
  }'
```

</CodeGroup>

Response `201`:

```json
{
  "payin_id": "9c2a…",
  "status": "pending",
  "charge": {
    "charge_id": "…",
    "qr_image": "<base64>",
    "qr_payload": "<QR content / copia e cola>",
    "our_reference": "482915073",
    "status": "pending"
  }
}
```

The `charge` object carries the collection data to display to your customer
(QR image/data, references). Its exact shape depends on the country's
method. In Brazil `qr_payload` is the PIX **"copia e cola"** code, so the
payer can paste it into their banking app instead of scanning the image.

When the QR is paid, your account is credited automatically and the
`payin_credited` webhook fires (see
[Receiving the credit](#receiving-the-credit)).

## Bank transfer (announced deposit)

Announce the incoming deposit and share the reference with the sender:

```bash
curl -X POST https://exchange.qbank.cl/platform/v1/payins \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "country": "CL",
    "currency": "CLP",
    "method": "bank_transfer",
    "amount": "500000"
  }'
```

Response `201`:

```json
{
  "payin_id": "4f81…",
  "status": "pending",
  "reference": "4f81…",
  "note": "include the reference in the transfer description so the deposit is credited automatically"
}
```

When the transfer arrives it is matched by the reference in the transfer
description (or by amount+currency as a fallback) and your account is
credited automatically.

## Active collection (pull)

In corridors that support it (for example Venezuela with `c2p` or
`debito_inmediato`), you charge the payer directly. The result is
**synchronous**: if the charge is approved, the credit lands in the same
call.

If the method requires an OTP, request it first (free):

```bash
curl -X POST https://exchange.qbank.cl/platform/v1/payins/collect/otp \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "method": "debito_inmediato",
    "amount": "1200.00",
    "payer_document": "V12345678",
    "payer_phone": "04141234567",
    "payer_bank": "0102",
    "payer_account": "01020123456789012345"
  }'
```

Response `200` — the payer receives the code from their bank:

```json
{
  "method": "debito_inmediato",
  "result": {
    "status": "sent",
    "otp_reference": "OTP-5521"
  }
}
```

Then execute the collection (payer fields depend on the method):

<CodeGroup>

```bash c2p (phone + ID + payer's OTP)
curl -X POST https://exchange.qbank.cl/platform/v1/payins/collect \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "method": "c2p",
    "amount": "1200.00",
    "description": "Order 5512",
    "payer_document": "V12345678",
    "payer_phone": "04141234567",
    "payer_bank": "0102",
    "otp": "12345678"
  }'
```

```bash debito_inmediato (account + previously requested OTP)
curl -X POST https://exchange.qbank.cl/platform/v1/payins/collect \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "method": "debito_inmediato",
    "amount": "1200.00",
    "description": "Order 5512",
    "payer_document": "V12345678",
    "payer_account": "01020123456789012345",
    "payer_bank": "0102",
    "payer_account_type": "CNTA",
    "otp": "87654321",
    "otp_reference": "OTP-5521"
  }'
```

</CodeGroup>

Response `200` (charge approved and credited):

```json
{
  "payin_id": "7b3c…",
  "kind": "collect",
  "method": "c2p",
  "status": "credited",
  "local_amount": "1200.00",
  "fx_rate": "36.50",
  "usdt_gross": "32.876713",
  "fee": "0.328768",
  "usdt_credited": "32.547945",
  "paid": true,
  "provider_reference": "…"
}
```

If the payer declines or the authorization fails, `paid` is `false`, the
payin is marked `failed`, and nothing is charged.

## Dedicated deposit account

In corridors that support it (for example Mexico), create a fixed deposit
account bound to your account — everything that arrives to it is credited
automatically, no references needed:

```bash
curl -X POST https://exchange.qbank.cl/platform/v1/payins/deposit-accounts \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{ "country": "MX", "currency": "MXN" }'
```

Response `201`:

```json
{
  "instrument_id": "a1d4…",
  "account_id": "…",
  "country": "MX",
  "currency": "MXN",
  "method": "bank_transfer",
  "instrument": "734180000151000006",
  "status": "active"
}
```

`instrument` is the destination you share with your payers (in Mexico, the
CLABE). Creation is free; each arriving deposit pays the regular payin fee.
List your accounts with `GET /v1/payins/deposit-accounts`.

## Receiving the credit

When the payment arrives (through any of the modes), your account is
credited automatically and the `payin_credited` webhook fires:

```json
{
  "payin_id": "9c2a…",
  "account_id": "…",
  "country": "BO",
  "currency": "BOB",
  "local_amount": "700.00",
  "fx_rate": "6.91",
  "usdt_credited": "100.310000",
  "fee": "1.000000"
}
```

The payin object keeps the full detail:

```bash
curl https://exchange.qbank.cl/platform/v1/payins/9c2a… \
  -H "Authorization: Bearer <token>"
```

```json
{
  "payin_id": "9c2a…",
  "kind": "qr",
  "status": "credited",
  "local_amount": "700.00",
  "fx_rate": "6.91",
  "usdt_gross": "101.310000",
  "fee": "1.000000",
  "usdt_credited": "100.310000"
}
```

## Statuses

| Status | Meaning |
|---|---|
| `pending` | Charge created, waiting for the payment |
| `credited` | Payment received and credited in USDT |
| `unassigned` | Deposit received without an automatic match (routed by the administrator) |
| `expired` | The charge expired unpaid |
| `failed` | The collection failed |

<Info>
Deposits arriving by direct transfer without a clear reference stay
`unassigned` until the CBPay team routes them to an account. Once assigned,
they are credited with the destination account's fees.
</Info>
