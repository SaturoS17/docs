## Create an account

```bash
curl -X POST https://exchange.qbank.cl/platform/v1/accounts \
  -H "Authorization: Bearer pk_…" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "company",
    "email": "finance@clientX.com",
    "display_name": "Client X SpA",
    "tax_id": "76543210-8",
    "country": "CL"
  }'
```

Two modes:

- **With login**: include `password` — the client signs in with
  email/password (`POST /v1/auth/login`) and manages its account.
- **API-first**: omit `password` (an unguessable random one is set) and
  issue the client an API key:

```bash
curl -X POST https://exchange.qbank.cl/platform/v1/accounts/{accountID}/api-keys \
  -H "Authorization: Bearer pk_…" \
  -d '{ "label": "clientX-backend" }'
```

The resulting `pk_...` token is shown **exactly once**; hand it to the
client over a secure channel.

## Query and update

```bash
# List (paged)
curl "https://exchange.qbank.cl/platform/v1/accounts?page=1&page_size=50" \
  -H "Authorization: Bearer pk_…"

# Detail
curl https://exchange.qbank.cl/platform/v1/accounts/{accountID} \
  -H "Authorization: Bearer pk_…"

# An account's balances and movements
curl https://exchange.qbank.cl/platform/v1/accounts/{accountID}/balances \
  -H "Authorization: Bearer pk_…"
curl https://exchange.qbank.cl/platform/v1/accounts/{accountID}/movements \
  -H "Authorization: Bearer pk_…"
```

### State and KYC

`PATCH /v1/accounts/{accountID}` updates profile, operational state and KYC
state:

```bash
curl -X PATCH https://exchange.qbank.cl/platform/v1/accounts/{accountID} \
  -H "Authorization: Bearer pk_…" \
  -d '{ "kyc_status": "approved" }'
```

| Field | Values | Effect |
|---|---|---|
| `status` | `active`, `blocked`, `closed` | `blocked`/`closed` prevent operating (payouts return `403 account_blocked`) |
| `kyc_status` | `none`, `pending`, `approved`, `rejected` | KYC process state; `pending` is set automatically when the client submits its screening |

<Info>
The full KYC flow: the client submits `POST /v1/kyc` (state becomes
`pending`), you review the screening result and resolve with `approved` or
`rejected`.
</Info>
