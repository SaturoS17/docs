## Crear una cuenta

```bash
curl -X POST https://exchange.qbank.cl/platform/v1/accounts \
  -H "Authorization: Bearer pk_…" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "company",
    "email": "finanzas@clienteX.com",
    "display_name": "Cliente X SpA",
    "tax_id": "76543210-8",
    "country": "CL"
  }'
```

Dos modalidades:

- **Con login**: incluye `password` — el cliente entra con email/contraseña
  (`POST /v1/auth/login`) y gestiona su cuenta.
- **API-first**: omite `password` (se genera una aleatoria no adivinable) y
  emite una API key para el cliente:

```bash
curl -X POST https://exchange.qbank.cl/platform/v1/accounts/{accountID}/api-keys \
  -H "Authorization: Bearer pk_…" \
  -d '{ "label": "clienteX-backend" }'
```

El token `pk_...` resultante se muestra **una sola vez**; entrégaselo al
cliente por un canal seguro.

## Consultar y actualizar

```bash
# Listar (paginado)
curl "https://exchange.qbank.cl/platform/v1/accounts?page=1&page_size=50" \
  -H "Authorization: Bearer pk_…"

# Detalle
curl https://exchange.qbank.cl/platform/v1/accounts/{accountID} \
  -H "Authorization: Bearer pk_…"

# Saldos y movimientos de una cuenta
curl https://exchange.qbank.cl/platform/v1/accounts/{accountID}/balances \
  -H "Authorization: Bearer pk_…"
curl https://exchange.qbank.cl/platform/v1/accounts/{accountID}/movements \
  -H "Authorization: Bearer pk_…"
```

### Estado y KYC

`PATCH /v1/accounts/{accountID}` actualiza perfil, estado operativo y estado
KYC:

```bash
curl -X PATCH https://exchange.qbank.cl/platform/v1/accounts/{accountID} \
  -H "Authorization: Bearer pk_…" \
  -d '{ "kyc_status": "approved" }'
```

| Campo | Valores | Efecto |
|---|---|---|
| `status` | `active`, `blocked`, `closed` | `blocked`/`closed` impiden operar (payouts devuelven `403 account_blocked`) |
| `kyc_status` | `none`, `pending`, `approved`, `rejected` | Estado del proceso KYC; `pending` se setea solo cuando el cliente envía su screening |

<Info>
El flujo KYC completo: el cliente envía `POST /v1/kyc` (queda `pending`),
tú revisas el resultado del screening y resuelves con `approved` o
`rejected`.
</Info>
